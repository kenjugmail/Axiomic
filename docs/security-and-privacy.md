# Axiomic — Security & Privacy

A one-page summary of how Axiomic handles authentication, uploads, AI,
code execution, signing, data, and vulnerability response. Intended
as a handout for college IT / compliance reviews and investor due
diligence.

## Authentication and sessions

- Session cookies: `httpOnly`, `SameSite=Lax`, `Secure` (HTTPS-only) in production.
- 30-day rolling session lifetime. Server-side session store; revocable.
- Passwords hashed with bcrypt via `Bun.password`.
- Development-only bypass (`DEV_AUTH_BYPASS`) is gated against `NODE_ENV=production` and refuses to run.
- Optional bootstrap-admin user is configurable via env; never has a default password.

## Cross-origin requests

- CORS origin allow-list is set per-deploy via `CORS_ORIGIN` (comma-separated; defaults rejected in production).
- CSRF protection comes from `SameSite=Lax` plus origin allow-listing. Cross-site form-submit attacks are blocked at the cookie layer for modern browsers.

## File uploads

- 10 MB cap per file.
- 200 MB cap per user (quota).
- Authentication required.
- Stored on a persistent disk volume (`UPLOADS_STORAGE_PATH`), never in-image, never in version control.
- Served with `X-Content-Type-Options: nosniff`.
- SVG explicitly denied (server-rendered SVG can stage stored-XSS).
- Path-traversal protections on the download path via `path.resolve` checks.

## AI provider

- Default: `mock` provider with canned responses (no external calls).
- Production may set `AI_PROVIDER=ollama` to point at a self-hosted Ollama instance for chat + embeddings. No third-party AI vendor required.
- Student data is never sent to external AI vendors by default. The mock provider is fully offline.

## Server-side code execution

- Default backend: `stub` — no code executes; the server returns a canned response.
- Optional `local` backend uses `Bun.spawn` with timeout + output caps. Intended for trusted-user deploys only; arbitrary public input requires a real sandbox (Docker / gVisor / firejail-class isolation) and is **not** enabled by default.
- Recommended pitch / public-demo configuration: keep `SERVER_EXEC_BACKEND=stub`.

## Signed transcripts

- ed25519 signature on every published capstone transcript.
- Public key is exposed at `/api/v1/keys/signing` and shown on the public verifier (`/verify`) so it can be pinned out of band.
- Private key (`AXIOMIC_SIGNING_PRIVATE_KEY_HEX`) is operator-supplied via env. Production refuses to start without it (and warns loudly otherwise). Generated by `scripts/generate-signing-key.sh`; never committed.
- Verification is offline: anyone with the public key can verify a transcript bundle without calling Axiomic at all.
- Manifest is canonical-JSON serialized before signing so signatures are reproducible across implementations.

## Data

- Storage: SQLite + Drizzle ORM. Single DB file on a persistent volume.
- No PII collected beyond username and optional email. Display name is user-chosen.
- All user-generated content (forum posts, comments, capstone writeups) is stored as plain text/markdown and rendered with an XSS-safe markdown pipeline.
- No third-party trackers in the production frontend bundle.
- Logs are structured JSON (pino). Optional Sentry integration via `SENTRY_DSN` for production error tracking; disabled by default.

## Content moderation

- Optional `CONTENT_APPROVAL_ENABLED=1` routes lesson + wiki edits through an admin-approval queue before they go live.
- Recommended for institutional deploys where faculty or admins must approve student-authored content.

## Vulnerability response

- GitHub Dependabot enabled (`.github/dependabot.yml`) — weekly grouped minor/patch updates, major versions opened individually for review.
- GitHub security advisories are monitored for the repo.
- Build pipeline gates: lint, typecheck, full unit test suite, E2E Playwright suite. CI must be green to merge.

## Operational hardening

- Rate limiting on expensive routes (AI, lessons, search, uploads). Process-local in-memory; can be swapped for Redis on multi-instance deploys.
- `/health` always-200 liveness; `/ready` pings DB + AI provider and returns 503 when degraded.
- Production env validation throws at boot — a typo in `CORS_ORIGIN` or `SENTRY_TRACES_SAMPLE_RATE` fails fast rather than silently falling back to defaults.

## Out of scope (and explicitly not promised)

- HIPAA / FERPA compliance. Axiomic is not currently a regulated-data-handler; do not store PHI or regulated student records on a vanilla deploy.
- Multi-tenant isolation. A single Axiomic deploy is single-tenant; isolation between schools requires separate deploys.
- Public arbitrary code execution. See "Server-side code execution" — public-facing exec needs sandboxing that ships on a future track.
